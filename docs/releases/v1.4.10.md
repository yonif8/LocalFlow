# LocalFlow 1.4.10

## Fixes

- **Send to WhatsApp no longer fires while you're in a text box.** In apps
  built on Chromium or Electron (Google Chrome, the Claude app and similar),
  LocalFlow sometimes couldn't read which element had focus yet, and 1.4.9
  treated "can't tell" as "no text box", so your dictation went to WhatsApp
  instead of being typed. Now LocalFlow sends to WhatsApp only when it can
  positively see that no text box is selected. If it can't tell, you get
  normal dictation.
- LocalFlow now asks Chromium and Electron apps to turn on their accessibility
  information when they come to the front (only while Send to WhatsApp is on),
  so the check gives the right answer straight away, including on web pages
  in Chrome.
- Password fields always count as text boxes.

## Updating

Use **Check for Updates** on macOS or Windows, or the in-app updater for the
recommended Linux AppImage. Debian/Ubuntu DEB users download and install the
new package manually.

## Validation scope

Unit tests cover the new focus classification, including the failed-lookup
case. On macOS, Chrome text fields, contenteditable areas and plain pages, the
Claude app's message box and a freshly launched Electron app were checked;
dictation into a Chrome text field was typed into the field, and a plain page
sent one message. Windows and Linux are unchanged.
