# LocalFlow 1.4.8

## Fixes

- **Transcription accuracy no longer degrades over time.** Since 1.4.5, long
  dictations are processed in the background at natural pauses. One slow run
  (a cold model after sleep, or a polish timeout) shortened later chunks, and
  short chunks then measured as slower still, until LocalFlow split speech at
  nearly every pause and stayed that way until it was quit. Each fragment was
  transcribed without the words around it, which broke sentences apart, lost
  number formatting ("$12,000" became "twelve thousand dollars") and cost
  word accuracy.
- Background chunks are now never shorter than 20 seconds, so dictations
  under 20 seconds are always transcribed in one pass. On slower hardware the
  release takes a little longer instead of fragmenting your speech.
- Processing speed is estimated from the median of recent long chunks, so a
  single slow run is forgotten instead of lasting until the app restarts.
  Chunks under 12 seconds no longer count toward the estimate.
- The same fix applies on Windows and Linux.

## Updating

Use **Check for Updates** on macOS or Windows, or the in-app updater for the
recommended Linux AppImage. Debian/Ubuntu DEB users download and install the
new package manually. If you can't update yet, quitting and reopening
LocalFlow restores full accuracy until the next slow run.

## Validation scope

The macOS suite and the portable C++ core tests cover the new chunking
policy, including regression tests for the collapse. Windows/Linux
application changes are covered by the automated release gate; hands-on
Windows/Linux testing remains deferred until those machines are available.
See [incremental dictation](../INCREMENTAL_DICTATION.md).
